# Контрольні питання до ЛР6 — відповіді

## 1. Що таке вимоги користувача?

Вимоги користувача — це сформульований користувачем перелік того, що він
очікує від продукту: які дії він виконує, які результати отримує і в
якому вигляді, яких помилок не допускає система. Вони описують поведінку
з погляду користувача, а не реалізації: без термінів структури коду,
таблиць БД чи інтерфейсів модулів. У життєвому циклі вимоги користувача
формуються на ранній спіралі (у проєкті — ЛР2) і в подальшому лише
уточнюються: у ЛР5 за ними спроєктовано негативні сценарії (нульова і
від'ємна кількість, невідомий товар), а в ЛР6 — розділ «Сценарії роботи»
керівництва користувача.

## 2. Що таке функціональна специфікація?

Функціональна специфікація — документ, який визначає, як продукт
реалізує вимоги: перелік функцій системи, їхні входи і виходи, правила
обчислення, реакцію на некоректні дані. Це місток між вимогами
користувача («кашир отримує суму до сплати») і реалізацією (функція
process_order повертає суму або None). У проєкті специфікація складається
із вимог R-01–R-06 (ТЗ, п. 3), правил знижок (0/5/10 % + 3 % картка),
умов відмови (невідомий товар, нестача, нульова або від'ємна кількість) і формату
результату (float, 2 знаки). Функціональна специфікація одночасно є
джерелом тестів: кожен пункт специфікації має тест-кейс (пакети T1–T3).

## 3. Які основні документи повинен містити перший рівень проектної документації?

Перший рівень проектної документації (за структурою ходу роботи ЛР6):

| Документ | Призначення | У проєкті |
|---|---|---|
| Технічне завдання (ТЗ) | постановка задачі, портрет користувача, вимоги | `docs/ТЗ_Магазин_Рошен.md` |
| Функціональна специфікація | як реалізовані вимоги | розділ 3 ТЗ + тести T1–T3 |
| Опис структури даних | схема даних прототипу (кандидат у таблиці БД) | ТЗ, п. 6 |
| Меню, діалоги й елементи керування | проєкт інтерфейсу: режими, меню, макети, гарячі клавіші | `docs/Меню_і_діалоги.md` |
| Керівництво користувача | сценарії роботи, формати даних, повідомлення | `docs/Керівництво_користувача.md` |
| HELP-файл (довідка) | структура довідки, повідомлення про помилки | `docs/HELP_Магазин_Рошен.md` |
| файл README | стартова точка: склад репо, запуск, тести | `README.md` |

Обов'язкового мінімуму три: ТЗ, функціональна специфікація та
керівництво користувача; README і HELP-файл додаються на тому ж рівні.
