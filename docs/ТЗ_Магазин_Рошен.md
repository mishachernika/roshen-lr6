# Технічне завдання на проектування ПЗ «Магазин Рошен»

Документ до лабораторної роботи № 6 «Документування результатів розробки
проекту програмного забезпечення». Дисципліна «Конструювання програмного
забезпечення». Варіант 13. Автор: Чернік Михайло, група ІПЗ-41.

## 1. Загальні відомості

- **Назва продукту:** ПЗ магазину «Рошен» (варіант 13).
- **Замовник:** адміністрація магазину «Рошен».
- **Розробник:** Чернік Михайло, група ІПЗ-41.
- **Призначення:** автоматизація розрахунку знижок та обробки замовлень
  торгівельної точки: обчислення суми до сплати за знижкою за обсягом і
  картою постійного клієнта, валідація замовлень, облік залишків складу.
- **Стадійність:** спіральна модель ЖЦ (ЛР1). Спіралі: ЛР1 — план,
  ЛР2 — вимоги, ЛР3 — структури даних, ЛР4 — реалізація та метрики,
  ЛР5 — тестування та відлагодження, ЛР6 — документація.

## 2. Психологічний портрет користувача

Користувач — касир або обліковець торгової точки, який:

- має навички роботи з клавіатурою, але не з бізнес-аналітикою;
- очікує результат одразу: суму до сплати або чітку підставу відмови;
- не повинен заповнювати поля, які система може вивести сама (ціни, залишки);
- робить помилки введення (нуль, від'ємне число, неіснуючий товар), тому
  кожна некоректна дія має завершуватися безпечним відхиленням без
  пошкодження обліку.

Наслідки для проектування: мінімальний набір даних, які вводить користувач
(товар, кількість, ознака картки); усі інші свідчення система видає сама;
повертане значення — єдиний результат, який касир інтерпретує.

## 3. Функціональні вимоги

| ID | Вимога |
|----|--------|
| R-01 | коректна сума зі знижкою: 0 % до 500 грн, 5 % за суми 500–999.99 грн, 10 % за суми 1000 грн і більше; наявність картки постійного клієнта додає 3 % |
| R-02 | замовлення з невідомим товаром відхиляється, склад не змінюється |
| R-03 | замовлення при нестачі товару відхиляється, склад не змінюється |
| R-04 | після успішного замовлення товар списується зі складу |
| R-05 | кількість товару — додатне число: нульова й від'ємна кількість відхиляється (вимога додана за результатами тестування ЛР5, D-01, D-02) |
| R-06 | демонстраційний сценарій виводить єдиний рядок результату |

## 4. Вимоги до надійності та якості

- відхилене замовлення ніколи не змінює складу (атомарність відмови);
- суми — з точністю до 0,01 грн;
- якість оцінюється за ISO/IEC 25010; цільові значення — у звіті ЛР5,
  таблиця 8; комплект тестів — 26 автоматизованих тестів, покриття 96 %.

## 5. Вимоги до інтерфейсу користувача

Продукт на поточній спіралі — консольний прототип, тому елементи ходу
роботи ЛР6 адаптовано так:

| Пункт ходу роботи (загальний випадок) | Реалізація в консольному прототипі |
|---|---|
| режими роботи, меню, піктограми, точки повернення | бібліотечний режим (виклик calc_discount / process_order), демонстраційний сценарій main(), тестовий режим (unittest discover) |
| типи діалогів | одиночний «виклик — результат»; повернення None означає відмову |
| командні кнопки, прапорці, списки, гарячі клавіші | відсутні; параметри функцій є аналогом полів діалогу |
| спливаючі підказки | docstring-рядки функцій містять ID вимог R-01–R-06 |
| довідка | файл docs/HELP_Магазин_Рошен.md |

Візуальну оболонку реалізовано у ЛР6 файлом `gui.py` (Tkinter): вікно з
полями товару й кількості, кнопки «Оформити»/«Скасувати», панель суми;
модуль розрахунку не змінено.

### 5.1 Вибір кольорів і шрифтів

Консольне подання (фактичне): моноширинний шрифт терміналу; кольорове
оформлення передається системі, у якій запущено продукт (Windows:
Consolas, світлий текст на темному тлі; Linux/macOS: типовий шрифт
емулятора терміналу). Результат успіху — сума звичайним кольором
тексту; відмова — рядок «Замовлення відхилено»: кодування відмови не
пов'язане з кольором, тому не залежить від підтримки кольорів ANSI.

Візуальна оболонка (план наступної спіралі). Палітра узгоджена з
фірмовим стилем «Рошен»: основний — темно-вишневий #B01E3C (заголовки,
панель меню, активні кнопки; білий текст на ньому — контраст 6.8:1),
акцентний — золотавий #D9A441 (рамка панелі суми, мітки; на золотому тлі
лише темний текст #333333 — контраст 5.6:1, білий текст на золотому не
використовується: 2.3:1), фон — білий #FFFFFF (поля вводу, таблиці), текст —
темно-сірий #333333 (12.6:1 на білому). Текст панелі суми — коричневий
#6B4A00 на світло-золотавому #FBF1DC (7.2:1). Усі пари «текст/фон» мають
контраст не нижче 4.5:1 (рівень WCAG AA). Колір не є єдиним носієм
інформації: відмова додатково позначається текстом і піктограмою «!».

Шрифти: інтерфейс — системний шрифт Windows (Segoe UI, 10 pt) з
запасним Tahoma, 9 pt; табличні дані (каталог, склад) — моноширинний
Consolas, 9.5 pt, щоб ціни й залишки вирівнювались по розрядах;
заголовки — Segoe UI Semibold, 12 pt. Кирилиця в усіх шрифтів —
повна; розмір менший за 9 pt не використовується навіть для підказок.

## 6. Вимоги до програмного забезпечення і даних

- мова: Python 3.8+; лише стандартна бібліотека; кросплатформеність —
  Windows, Linux, macOS;
- запуск: `python gui.py` (візуальна оболонка, основний режим),
  `python roshen_shop.py` (демонстрація), `python -m unittest discover -s tests` (тести);
- схема даних (поточне подання в словниках; кандидат у таблиці БД):

| Структура | Поля | Тип |
|---|---|---|
| prices (прайс-лист) | name: price | str: int, грн за одиницю |
| stock (склад) | name: quantity | str: int, шт |
| order (замовлення) | name: quantity | str: int, шт |
| is_member | ознака картки клієнта | bool |

Результуюче значення: сума до сплати (float, 2 знаки) або None — відмова.

## 7. Приймання

Продукт приймається, якщо: 26/26 автотестів пройдено (одна команда),
демонстраційний сценарій виводить «До сплати: 680.8», після внесення будь-
якої зміни регресійний прогін зберігає 100 % пройдених тестів.
